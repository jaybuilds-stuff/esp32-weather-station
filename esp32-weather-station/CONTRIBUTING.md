# Contributing

Thanks for your interest in contributing to Weather Station!

Contributions are welcome, whether you're fixing a bug, improving the code, updating documentation, or suggesting new features.

## Getting Started

1. Fork this repository.
2. Clone your fork to your computer.
3. Create a new branch for your changes.
4. Make your changes and test them if possible.
5. Commit your changes with a clear message.
6. Open a pull request describing what you've changed.

## Development Guidelines

- Keep the code clean, readable, and easy to maintain.
- Use meaningful variable and function names.
- Write code and comments in English.
- Avoid unnecessary dependencies.
- Follow the existing project structure and coding style.
- Make sure your changes don't break existing functionality.

## Reporting Bugs

If you find a bug, open an issue and include:

- A description of the problem
- Steps to reproduce it
- Expected and actual behavior
- Your ESP32 board and hardware configuration
- Relevant error messages or logs

## Suggesting Features

Have an idea for improving Weather Station? Feel free to open an issue.

Describe what you'd like to add, why it would be useful, and how it might work.

## Pull Requests

Before submitting a pull request:

- Make sure your code compiles.
- Test your changes on an ESP32 if possible.
- Keep pull requests focused on one improvement or fix.
- Explain what you've changed and why.
- Update the documentation if necessary.

## Security

**Never commit Wi-Fi passwords, API keys, or other sensitive information.**

Use `secrets.h` for local credentials and keep it excluded from Git using `.gitignore`.

If you discover a security issue, avoid publishing sensitive details or credentials in a public issue.

## Code of Conduct

Be respectful and constructive when discussing issues or reviewing contributions.
